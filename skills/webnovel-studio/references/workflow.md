# 工作流

本文件用于判断网络小说任务该怎么做，并保证长篇项目稳定推进。

## 任务分流

新书项目：
1. 明确平台、频道、题材、目标读者、读者承诺、语气、禁忌边界和目标字数。
2. 如果用户需要市场方向，先用公开来源调研，再决定选题。
3. 使用 `scripts/init_project.py` 创建项目文件，或按 `project-files.md` 手动创建。
4. 建立核心设定：题材承诺、书名备选、简介、主要人物、金手指和世界规则。
5. 设计嵌套结构：全书、升级梯、第一卷/地图、前 30-50 章篇章、前 3-10 章小篇章、前 5 章。
6. 只有当前 5 章有明确节拍、第一篇章有明确高潮后，才开始写第 1 章。

已有项目：
1. 先读取项目文件。
2. 将用户请求与事实库、章节计划和嵌套结构对照。
3. 如有冲突，先报告冲突并给出修复建议。
4. 再写作、审稿并更新连续性记录。

章节审稿：
1. 读取章节和相关事实文件。
2. 按商业阅读体验评分。
3. 检查七步章节结构，以及该章节在当前小篇章/篇章中的作用。
4. 找出最影响留存的 3 个问题。
5. 按需改写局部或整章。
6. 记录影响事实库的改动。

## 单章循环

每一章都应经过：

1. 读取事实库和上一章摘要。
2. 确认本章目标、冲突、爽点、结尾钩子，以及当前篇章/小篇章功能。
3. 按七步结构写正文。
4. 按审稿标准评分。
5. 做连续性检查。
6. 更新章节台账、时间线、人物状态、伏笔表和最新摘要。

## 长篇循环

每 3-5 章：
- 检查是否有小爽点、小回报或明显地位变化。
- 检查至少一条升级梯是否前进。

每 8-12 章：
- 检查是否有敌人升级、公众评价变化或地图压力提升。

每 20-50 章：
- 完成一次篇章高潮，带来资源收获、秘密揭露、地位变化和下一篇章钩子。

## 停止条件

遇到以下情况，先停下，不要硬写：

- 用户要求事实性平台分析，但没有可用来源。
- 章节计划与事实库冲突。
- 用户要求的剧情破坏既定战力、死亡状态、时间线或人物关系。
- 新篇章缺少反派压力、信息差或收获。
- 用户要求模仿具体在世作者，或过度贴近已知作品。
- 任务依赖私有平台数据、绕过登录或绕过反爬。
