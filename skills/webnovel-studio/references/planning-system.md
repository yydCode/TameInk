# 策划系统

本文件用于在写正文前设计新书。

## 必须先完成的策划项

写章节前先建立：

- 平台和频道。
- 题材组合。
- 目标读者。
- 一句话读者承诺。
- 商业钩子。
- 主角欲望、伤口、缺陷和主动优势。
- 核心冲突。
- 金手指或特殊设定。
- 主要反派压力。
- 长篇连载引擎。
- 全书结构。
- 升级梯：战力、地位、敌人、秘密、资源、关系、地图。
- 第一卷或前 50 章结构。
- 前 5 章计划。
- 30-50 章篇章计划。

使用 `novel-architecture.md` 设计全书、卷、篇章、小篇章、章节和场景的嵌套结构。

## 题材卖点测试

一个可用的商业设定必须回答：

1. 主角是谁？
2. 开局有什么紧急问题？
3. 和常见模板相比，有什么差异化？
4. 每几章能重复给出什么回报？
5. 哪个更大的秘密或敌人能支撑长篇？
6. 第 1 章结束后，读者为什么必须继续看？

如果一句话说不清卖点，就先简化。

## 全书测试

细化章节前先确认：

1. 开局劣势是什么？
2. 主角凭什么打破劣势？
3. 最终压力或最终敌人是谁？
4. 哪些升级梯能让读者每几章看到进度？
5. 哪个秘密可以分层揭露，而不是一次讲完？
6. 后续有哪些新地图避免重复？
7. 全书承诺的最终地位变化是什么？

## 书名生成

书名要表达题材、主角位置、核心设定和回报。避免复制已知书名。

常见商业书名模式：

- 重生/觉醒/绑定 + 核心设定 + 回报。
- 开局 + 危机/行动 + 意外优势。
- 身份反转 + 目标。
- 灾难/倒计时 + 生存行动。

评估书名时看：清晰度、新鲜感、平台适配、原创安全。

## 人物设计

主要人物按这个格式记录：

```markdown
## 人名

角色功能：
年龄：
身份：
目标：
筹码：
秘密：
与主角关系：
当前态度：
说话/行为标记：
状态：
首次出场：
事实约束：
```

反派要有可信筹码和动机。盟友要有用处、冲突潜力和留下来的理由。

## 金手指设计

记录：

```markdown
名称：
触发方式：
能做什么：
不能做什么：
代价/风险/冷却：
成长路径：
敌人如何施压：
如何制造新麻烦：
前 5 次使用：
```
