# 章节写作

本文件用于起草、续写或重写章节。

## 写作前必须读取

写作前先读取或建立：

- `brief.md`
- `story-bible.md`
- `chapter-plan.md`
- `characters.md`
- `world-rules.md`
- `timeline.md`
- `foreshadowing.md`
- `chapter-ledger.md`
- `previous-summary.md`
- `style-guide.md`

如果这些文件不存在，而任务只是一次性样稿，先说明临时假设再写。

## 起草检查清单

一章至少要有：

- 前 300 中文字内出现钩子。
- 主角本章短期目标明确。
- 冲突或压力尽早出现。
- 主角至少做一次主动选择。
- 至少一个情绪回报或有意义的损失。
- 结尾时局面发生变化。
- 章末钩子指向下一章。
- 七步结构可见：优势亮相、反派抬高、初次摩擦、信息差、反转、震惊效果、收获与钩子。

## 章节结构

默认使用七步起承转合结构。详见 `seven-step-structure.md`。

1. 起：开场与主角优势亮相。
2. 承：反派登场，抬高地位或后台。
3. 承：第一次交集和摩擦。
4. 转：用信息差拉期待。
5. 转：冲突爆发并打出反转。
6. 合：震惊效果和反差爆发。
7. 合：收获与下章钩子。

如果是短章或过渡章，可以压缩步骤，但不能省掉冲突、爽点和钩子。

## 正文质感规则

- 像现场正在发生一样写，不要像作者在解释设定。
- 能用动作和反应表达，就少用解释。
- 情绪变化要具体：笔停住、笑容僵住、袖口遮手、房间安静、有人话说半截停下。
- 系统文字要少而准，像一把刀插进场景，不像说明书。
- 不要用论文式或总结式段落收尾。
- 不要用空泛口号结尾。结尾必须落到具体威胁、发现、选择或不可逆行动上。
- 不模仿具体在世作者，用通用商业技法：钩子、压力、反转、反应、悬念。

## 输出格式

写章节时输出：

```markdown
# 第X章 标题

正文...

---

## 章节元数据

钩子：
主角目标：
主要冲突：
情绪回报：
金手指使用：
新增事实：
变更事实：
新增伏笔：
回收伏笔：
连续性风险：
下章钩子：
七步检查：
1. 起/优势亮相：
2. 承/反派抬高：
3. 承/初次摩擦：
4. 转/信息差：
5. 转/反转：
6. 合/震惊效果：
7. 合/收获与钩子：
```

如果用户要求只要干净正文，可以不展示元数据，但内部仍要按元数据检查。

## 风格规则

- 语言直接、易读；除非用户要求文学化，否则不要过度修辞。
- 感官细节只服务压力和场面，不拖慢节奏。
- 短段落适合移动端阅读。
- 避免长篇讲课、重复内心戏和冗余对话标记。
- 爽点要写人物反应，反应会放大爽感。
- 避免复制具体作者文风或已知作品剧情。

## 改写模式

轻度改写：
- 保留剧情和事实。
- 改善节奏、清晰度、对话和钩子。

商业化改写：
- 保留核心事实。
- 强化冲突、爽点、章末钩子和读者承诺。

结构性改写：
- 调整场景顺序或剧情节拍。
- 同步更新章节台账和事实影响记录。
