# 连贯性系统

本文件用于防止事实幻觉、剧情跑偏、战力崩坏、伏笔遗忘和人物漂移。

## 事实库文件

以下文件视为事实来源：

- `story-bible.md`：最高优先级，记录核心设定和不可违背事实。
- `characters.md`：人物姓名、身份、关系、目标、状态。
- `world-rules.md`：系统、战力、科技、法律、地理、组织。
- `timeline.md`：日期、事件顺序、截止时间、年龄逻辑、过去事件。
- `foreshadowing.md`：已埋线索、未解决钩子、回收计划。
- `chapter-ledger.md`：逐章事实记录。
- `previous-summary.md`：最新剧情状态摘要。

## 写作前连续性检查

写每章前确认：

- 谁在场？
- 场景发生在何时何地？
- 相关人物此刻知道什么、不知道什么？
- 角色有哪些资源、伤势、能力、债务、秘密和关系状态？
- 哪些未解决钩子仍然有效？
- 哪些事实规则会限制本章解法？

## 写完后的更新格式

每章写完后更新：

```markdown
## 第X章

时间：
地点：
主角目标：
主要冲突：
本章结果：
新增人物：
新增设定：
人物关系变化：
资源/地位变化：
金手指使用：
战力/能力变化：
新增伏笔：
回收伏笔：
未解决问题：
下一章承接：
```

如有影响，还要更新人物状态、时间线、世界规则和伏笔记录。

## 跑偏检查

出现以下情况要标记问题：

- 人物姓名、年龄、身份、关系或动机无原因变化。
- 已死亡、离场、受伤、被关押或不知情的人物突然正常行动或知情。
- 金手指无铺垫获得新能力。
- 为解决场景而破坏战力或世界规则。
- 时间线事件过早、过晚或重复发生。
- 已解决冲突被当作未解决重复写。
- 已埋伏笔超过回收窗口仍被遗忘。
- 新章节创造重要势力、能力、敌人或秘密，却没有写入事实库。
- 故事偏离平台承诺或题材方向，且没有计划中的过渡。

## 设定变更流程

必须改设定时，用这个格式：

```markdown
## 设定变更提案

当前事实：
新版本：
变更原因：
影响文件：
影响章节：
风险：
建议迁移方案：
```

不要静默修改重大设定。

## 事实状态标签

不确定时使用这些标签：

- 既定事实：已经确立。
- 新事实：本章新增，需要记录。
- 临时假设：等待用户确认。
- 传闻：故事内角色的说法，可能为假。
- 谜团：故意未解。
- 冲突：与既定事实矛盾，需要修复。
